# 4.0 verification scope

The release gate on Windows / Node 24.21 ran 509 offline tests: 508 passed, none failed, and the POSIX FIFO test was skipped on Windows. Tests use isolated stores, synthetic credentials, a network block and the actual pinned official SDK with a local provider fixture. Packaging checks passed 3/3 and inspected the actual npm archive.

Coverage includes literal context retention across twelve followups and an owner restart, twelve alternating SDK activities, native inject/steer, idle messages without inference, question/reply, concurrent identical followups, interruption and resume, uncertain-delivery refusal, scoped compaction/Teams context, single-request boundaries and old-writer protocol fencing. Deterministic gates cover final-publication/lease-release, interrupted followup handoff, deferred-write connection shutdown and closing-head publication before transaction unlock.

An authorized real campaign used two independent MCP connections and three workers: a CSV ledger implementer, an independent oracle/reviewer, and a DAG scheduler with native Teams. Seven activities produced complete results; independent parent checks passed 68 ledger cases and 7 scheduler cases. Final documentation/static-review activities used no Shell. The campaign recorded 213 finished model requests; two calls lacked token fields and cost was unavailable. Separate MCP connections are not a claim that this campaign created two Codex UI chats.

Native Teams member communication and cleanup were exercised, but recovery was not uniformly successful: a provider malformed tool response was followed by replacement-member wake/reassignment trouble. Four member sessions served two logical roles. Final artifact acceptance does not certify efficient Teams recovery. See [persistent worker limitations](agent-communication.md#verification-limits).

The design's full combined training/compaction/question/Teams/crash narrative was not executed as one scenario. Exact post-enqueue/pre-ack crash timing, question while a real Teams child remains active, progress-flood latency and abrupt external process termination remain distinct stress cases. Mechanism tests and parent artifact checks do not establish infinite physical context, exactly-once external side effects or general model correctness. Current installed-host activation is verified separately during deployment.
