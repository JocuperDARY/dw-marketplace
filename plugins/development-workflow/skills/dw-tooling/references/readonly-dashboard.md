# 只读监控台

用于已有任务、服务或计算工作的观测界面。授权与证据原则见 [总纲](../../development-workflow/SKILL.md#授权资源与内部前置条件)，后台服务的启动、身份确认和清理见 [资源生命周期](../../dw-collaboration/references/resource-lifecycle.md)。本规范适用于页面、终端界面或只读 API，不要求特定框架、操作系统或调度平台。

## 先确定读者需要判断什么

围绕当前任务、进度、最近结果、异常与待处理事项组织界面；历史运行和已替代结果放在可辨认的历史区域。展示用户实际需要的指标，不因模板列有 GPU、进程、主机启动时间或多 agent 就要求每个平台提供它们。

让读者能从概览进入对应证据：状态来自哪里、何时观察、是否仍新鲜、缺了什么。名称使用项目已有术语；失败、未知和过期不能只靠颜色区分。刷新不应抢走焦点或反复重排正在阅读的内容。

按目标设备检查窄屏、键盘操作、焦点与对比度。区分加载、空态和错误；没有活动任务时显示合法空态。调整布局时保留重要的历史关系、趋势和证据入口，避免改版丢失可追溯信息。

## 数据来源与状态

- 每项关键结论有明确来源，例如运行器状态、产物元数据、日志事件或任务记录。沿用现有标识和状态定义，转换规则只在负责归一化的模块维护；前端可做展示、筛选与聚合，不另造一套成功判定。
- 分开记录来源时间与采集时间；来源没有时间戳时明确说明。过期阈值按数据更新规律确定；历史终态产物与活跃进度采用各自适用的规则。
- 展示旧的成功观测时标出时间和过期状态。来源不可达、解析失败、权限不足与合法空值分别处理，不能用缓存成功值伪装当前正常，也不能把未知或缺失补成零。
- 区分被观测任务的状态与观测工具自身的健康。页面在线、HTTP 成功、文件存在或进程存活，各自只证明对应事实；任务完成以任务的验收证据为准。
- 当前运行与历史运行绑定到正确的任务或运行标识。主机重启可能导致 PID 或计数器复用时，再引入该平台可用的启动标识或等价证据；不把某个操作系统字段设为所有数据源的必填项。
- 分母与计数范围明确：已完成、运行中、失败、暂缓、未知是否纳入总数，按项目含义说明。重试、重复消息和历史结果不能重复计为新的完成项。

多文件读取可能跨越状态变更。优先使用来源提供的一致快照或版本标识；无法保证一致时说明采样窗口和限制。只有传输、归档或具体完整性协议需要时才增加摘要校验，不以每次刷新计算全目录哈希代替来源管理。

## 接口只读与信息保护

只读接口提供查询与静态资源，不接受运行控制、参数修改、停止任务或删除产物等动作。GET/HEAD 也不能触发这些副作用；确有跨域预检需求时可支持 OPTIONS。维护部署使用独立工具与权限，不把写操作藏在页面按钮或查询参数中。

数据源和服务根目录有明确范围。检查路径穿越、链接越界、日志中的密钥和个人信息、错误堆栈泄漏，以及来源文本进入 HTML 时的注入风险。结合框架选择转义、内容安全策略和访问控制，不将一个框架的配置名当作通用接口。只读并不表示信息可以公开。

本地使用优先限制监听范围；远程访问按实际网络和用户授权设计认证、传输保护及可见字段。平台已有身份机制时复用它，不因引入监控台要求同一用户反复授权。没有授权的对外暴露仍须先明确范围。

## 服务与更新

维护一个明确的日常访问入口，复用已有服务。隔离的预览或测试实例可以短期并存，但要区分数据来源、端口和责任人，并在完成后清理本任务的实例。端口被占用时先核实占用者；不得凭名称或端口停止未知进程。

持续使用的监控台要有维护责任和适合来源的更新机制；普通任务由现有负责人兼任即可，不必设置一个长期空闲的专职 agent。

在既有修改与部署授权内，可执行影响明确、可恢复的界面或采集器更新。先判断更新是否会重启服务、改变数据源权限或干扰被观测工作；新增外部暴露、实际超出授权的部署或影响运行中任务时，再取得缺少的决定。用户只要求查看或设计时，不据此自动部署。

观测器与任务控制解耦：采集失败不应停止被观测任务。轮询频率、退避和读取量与来源承载能力匹配；有事件订阅时可复用，不强制所有平台实现推送。服务退出时只回收本任务拥有的资源。

## 验证与交付

按 [观测与协作工具的验证](../../dw-verification/SKILL.md#观测与协作工具的验证) 选择覆盖实际风险的用例。测试数据与真实状态清楚标识；以模拟输入验证页面不能宣称真实运行已完成验收。交付说明当前入口、观测范围、刷新方式和已知限制即可，不另建一套任务事实记录。
