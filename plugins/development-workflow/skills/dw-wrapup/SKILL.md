# 收尾与知识持久化

> 本 skill 是 [development-workflow](../development-workflow/SKILL.md) 的子模块，覆盖 **证据整理、必要文档同步、资源清理与提交准备**。遵循铁律 A3（按已有授权执行）、B6（重要修改的记录与恢复）。

---

## 文档更新清单

只更新仓库已有规范要求、且本次行为或契约确实发生变化的文档：

| 变化 | 可能需要更新 |
|------|--------------|
| 用户可见行为/API/配置 | 对应使用指南、API 文档、示例或 changelog |
| 架构、数据契约或运维方式 | 现有设计/运行手册、schema、决策记录 |
| 性能或容量承诺 | 现有基准报告，含工作负载与环境 |
| 纯内部且无契约变化 | 通常无需新建概要或历史文档 |

不要为了完成清单创建仓库不存在的 `SYNOPSIS.md`、优化报告或“已知坑位”章节。

---

## 知识持久化

优先把确有复用价值的结论写入仓库已有文档。外部持久化知识库仅在当前运行时可用、用户已授权且内容完成脱敏时使用：

| 知识类型 | 内容 | 示例 |
|---------|------|------|
| **Bug 记录** | 根因机制、修复方案、如何防止回归 | "缓冲区类型不匹配导致全零输出" |
| **经验教训** | 从修复过程中发现的适用条件与模式 | "应有信号的字段全零时，核对输入和执行状态" |
| **工作规则** | 从具体经验中提炼的有条件约束 | "任务要求实测的新字段需定义缺失状态与失败条件" |

---

## 版本保留

- 复用 Git 历史、现有备份和发布归档保存可恢复版本（B6）。
- 保留独有产物、历史失败和关键决策。清理重复文件前确认恢复来源和用户要求。

---

## 提交准备

- 按用户最新指令复用已有的暂存、提交、推送及 PR 授权，保留实际设定的次数、时限和撤销条件（A3）；目标或操作超出授权时再确认。
- 暂存前检查工作树，逐项选择本任务文件。
- 提交说明包含改动目的、相关检查和实际剩余问题。
- 发布版本按总纲迭代规则处理；同一次 PR 的修订沿用该候选版本。

---

## 工作历史同步

仓库已有工作历史或决策记录、且本次变化值得长期保留时，记录：
- 做了什么改动
- 为什么做这个改动
- 结果如何（对应验收证据，能量化时提供指标）
- 涉及哪些文件

## 自有资源清理

普通前台命令根据宿主退出结果和本任务资源记录确认结束。对本任务单独启动的后台资源，在完成、失败或中断时正常停止并确认退出；涉及监听端口时确认释放。只处理已确认属于本任务的资源，保留用户产物与诊断证据。

身份或退出证据不足时保留 `HOLD`/`UNVERIFIED`，如实报告资源标识、当前状态和所缺证据。异常残留、强制终止、事故恢复和显式资源管理协议的身份、观测、路径与恢复要求统一见 [resource-lifecycle](../dw-collaboration/references/resource-lifecycle.md)；普通完成无需为此额外建立监测基线。

## 基线对比记录模板

性能、容量或资源优化使用以下模板。普通功能/修复记录相关验收命令和结果即可，不强造数值基线：

```markdown
## 基线对比记录

| 指标 | 改动前 | 改动后 | 变化 | 判定 |
|------|--------|--------|------|------|
| 响应时间 P50  | 120ms            | 45ms             | -62.5% | ✅ 通过 |
| 响应时间 P99  | 850ms            | 210ms            | -75.3% | ✅ 通过 |
| 吞吐量        | 800 req/s        | 2400 req/s       | +200%  | ✅ 通过 |
| 错误率        | 0.5%             | 0.5%             | 持平   | ✅ 通过 |
| 峰值内存      | 512 MB           | 548 MB           | +7%    | ⚠️ 接受 |

**对比条件**：
- 测试数据：经授权且脱敏的代表性回放，或能覆盖正常/异常/边界的合成负载
- 配置参数：Cache-Aside 模式，TTL=300s
- 随机种子：42
- 硬件：4 vCPU, 8 GB RAM, SSD
- 评估脚本：`scripts/benchmark.sh`

**基线 commit**：`a1b2c3d`（改动前最后一次 commit 的 hash）
```

> **原则**：性能声明缺少同口径基线是不完整的；其他变更使用最能证明验收条件的证据。

## 收尾阶段反模式

| 反模式 | 后果 | 正确做法 |
|--------|------|---------|
| 行为/契约变化但文档不更新 | 使用者依赖过时说明 | 更新仓库中对应的既有文档 |
| 结论只留在临时对话 | 后续无法复用 | 写入合适的仓库文档；外部知识库需可用且获授权 |
| 超出授权提交或推送 | 改变了用户未决定的外部状态 | 沿用已有授权，新增范围先明确 |
| 一次性暂存全部文件 | 混入用户或无关改动 | 仅暂存用户要求且属于本任务的文件 |
| 留下开发服务器或子进程 | 占用端口和资源，污染后续任务 | 按所有权记录回收并验证退出 |
| 性能声明不记录基线 | 无法证明改动有效 | 记录代表性工作负载的同口径前后数据 |
| 覆盖独有历史资料 | 无法回溯与修复 | 保存可恢复副本后再整理（B6） |
