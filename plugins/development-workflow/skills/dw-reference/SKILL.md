## 完成前简查

- 当前结果符合已确认目标与适用计划，受影响路径有对应证据。
- 适用检查的实际结果、未验证部分和残余风险已明确。
- 敏感信息和无关用户改动受到保护，重要修改有可恢复来源。
- 后台资源只按已确认的任务所有权正常停止并确认退出；身份或结果不明时保留未知状态并按资源协议处理。
- 必要文档与待办有去处，外部操作在用户现有授权范围内。

三 C、诊断分类和严重度使用上方主文档，不另设快速参考版本。

## 附录 A：合成测试数据设计原则

1. **Oracle 可解释**：优先使用解析解、独立实现或明确领域不变量，不把被测算法自身输出当真值。
2. **变换覆盖风险**：从最简单可判定案例开始，再加入真实会触发缺陷的复杂度。
3. **输入满足前置条件**：同时覆盖有效、边界和无效输入，避免只生成算法最擅长的数据。
4. **可复现随机**：记录种子、生成器版本和关键参数。
5. **容差预先定义**：按数值尺度和业务误差预算设定，不在看到结果后放宽。

## 附录 B：GPU 计算开发专项注意事项

1. **异步边界**：仅在主机读取结果、跨流依赖或性能计时边界做必要同步，避免逐操作同步破坏并行性。
2. **缓冲区契约**：验证 shape、dtype、布局、设备和生命周期与 API 约定一致。
3. **计算方向约定**：对输入/参考方向、坐标系和符号约定做可判定对照测试。
4. **数值表示**：定点缩放、精度、溢出和舍入策略进入测试边界。
5. **领域不变量**：只在契约要求时断言非全零；同时覆盖合法全零、空输入和不适用状态。
