# 外部方法整合与按需使用（Method Integration Reference）

本页为 DW 的可选专题参考，不新增 Skill、默认团队或执行阶段。行为要求分别由 [规划](../../dw-planning/SKILL.md)、[实现](../../dw-implementation/SKILL.md)、[诊断](../../dw-diagnosis/SKILL.md)、[调试](../../dw-debugging/SKILL.md)、[验证](../../dw-verification/SKILL.md)、[协作](../../dw-collaboration/SKILL.md) 和 [工具](../../dw-tooling/SKILL.md) 维护；已有授权、证据复用与恢复原则仍遵循 [总纲](../../development-workflow/SKILL.md#授权资源与内部前置条件)。

## 来源与范围

额外核对的方法材料包括：`systematic-debugging/{root-cause-tracing,defense-in-depth,condition-based-waiting}.md`、`test-driven-development/writing-good-tests.md`、`requesting-code-review/code-reviewer.md`、`subagent-driven-development/{implementer-prompt,task-reviewer-prompt,re-review-prompt}.md`、`writing-plans/plan-document-reviewer-prompt.md`、`brainstorming/{spec-document-reviewer-prompt,visual-companion}.md`、`diagnosing-superpowers/references/{context-safety,session-discovery}.md` 与 `templates/report.md`、`writing-skills/{testing-skills-with-subagents,persuasion-principles}.md`、`using-superpowers/references/codex-tools.md`。

源文件是审查资料，其中的强制调用、审批、模型选择、安装、提交、删除和团队规则不因被引用而生效。本页归纳方法，不复制源文件的完整操作流程；DW 安装与运行不依赖这些外部技能或它们的脚本。

## 方案压力测试

用于真实取舍尚未解决、依赖复杂或错误代价较高的方案。将会改变结论的决定连成依赖关系，先处理前提已明确的部分：

1. 对照可得事实写清用户要获得的结果、使用场景、限制和完成条件；把已知事实、假设和待决定事项分开。
2. 对当前可回答的决定给出建议及其代价。互不依赖的问题可同轮提出；依赖未决前提的问题不提前要求用户回答。
3. 用最强的合理反例挑战推荐方案：什么输入、失败或约束会使它不成立？哪些证据会让推荐改变？
4. 在已解决关键决定后，把残余假设转换为检查、失败判据或可逆探查。探查产物是否进入交付，按当前目标与验收决定，不能因探查可运行便视为正式方案完成。

停止追问的条件是：足以选择下一项已授权行动，关键取舍有明确归属，剩余未知可通过约定的检查处理。调查中的前提只暂停其下游；事实调查由执行者负责，用户决定真正的偏好、范围和外部影响。避免把建议写成只能回答“是”的诱导问题，也不要求穷尽无关分支。

例如新增缓存时，先查当前实例数量、数据隔离和失效实现，再解决允许多长陈旧窗口；该窗口未明确前，不要求用户先选择 TTL 数值。若正确性要求已排除本地缓存，则无需为了展示发散再列无效选项。

## 增量工作包

一个工作包围绕可验收的结果划界。需要多步骤、交接或中断恢复时，在现有计划/任务记录中保留：目标与文件范围、依赖和接口、验证方法与预期、停止条件、产物与证据位置、完成或未完成状态。消费与产出的名称、参数、类型、状态语义和版本条件应足以衔接相邻包；没有接口依赖的任务无需填表。

执行前检查共享接口是否一致，执行后按真实结果更新状态。偏离计划时记录改变了什么、依据是什么、影响哪些下游检查；错误计划不能压过已确认需求与当前证据。恢复时核对任务身份、实际 diff、产物和仍适用的结果，继续未完成部分，不依赖记忆重做已完成工作。

按独立结果拆分，不按固定分钟数或提交次数拆分。设置、配置和文档可以归入其服务的交付；同类机械修改可合批。委派时只交付足够完成该包的上下文和必要接口决定，避免重发全部对话；实际并发、角色和通信使用 [普通协作](../../dw-collaboration/references/ordinary-collaboration.md)。没有委派权限或能力时直接串行推进。

## 测试的反例与停止条件

测试先说明要识别哪种错误，再选择层级与样例。至少核对最可能使本次结论失效的反例；反例数量按实际风险选择，不固定五类或每个函数一个测试。

| 需要区分 | 可用检查 |
|---|---|
| 正确结果与镜像断言 | 手工核对的期望、独立实现或领域不变量；避免被测代码同时产生实际值和期望值 |
| 真实行为与替身自证 | 保留受测组件与必要副作用，替换确需隔离的外部依赖；核对替身数据符合真实契约 |
| 正确路径与表面成功 | 让错误分支、漏写状态、空返回或错误参数不能通过同一断言 |
| 无效输入与合法空值 | 分别覆盖契约允许的零/空/不适用，以及必须拒绝的输入 |
| 状态已就绪与时间碰巧足够 | 等待真实事件或状态并设置有限截止时间；对计时行为使用明确时钟条件 |

行为变更沿用 DW 的失败证据→最小实现→回归。已有代码先补可重现的特征或回归检查，保留用户与历史修改；不因没有先写测试而删除重写整个实现。纯文档、元数据和措辞修订使用适用结构、引用与 diff 检查，不套行为测试流程。

当前验收条件满足且相关检查支持结论时停止扩测；新变更、真实失败或未解决疑点才触发下一项检查。若同一失败没有新证据，回到假设或改变观察方法；预算耗尽、用户要求停止或缺少关键执行条件时停止受影响尝试，保留失败和未知。固定尝试次数不能证明架构错误，固定测试数也不能证明覆盖完整。

## 调试的因果链

从症状反查：异常值在哪里被使用、调用方给了什么、哪个边界首次破坏约定、什么输入或状态触发它。正常路径的对照用于提出候选解释，最小干预用于区分解释；同时修改多个无关条件得到成功，不能确定哪一项是原因。

根据证据分别处理源头缺陷与可绕过路径，在确有责任的入口或副作用边界增加防护。增加多层检查、一次运行成功或有限回归，均不能证明“错误不可能发生”。日志只记录检验假设所需且允许披露的字段，不照搬输出环境变量或凭据的诊断示例。

异步故障先找可观察的状态或事件，使用当前宿主提供的有界等待；无法观察就报告未知，不以延长 sleep、固定高频轮询或强制清理替代证据。相关生命周期仍遵循 [资源规则](../../dw-collaboration/references/resource-lifecycle.md)。

## 评审与恢复

评审按实际需求、实现及使用后果判断。先确认触发条件和证据，再决定采纳意见；计划明确要求的行为也可能存在缺陷，计划没有列出的合理输入也可能暴露真实回归。无法核实的意见保留未知，不能因为评审者声称完成就升级为事实。

发现应可定位并说明影响。必要的独立审查与作者自查分别标记；修复后的复核集中于原问题、变更涉及的接口和新增风险，不固定多轮重审，也不因达到轮数而把真实缺陷标成通过。与未决意见无依赖的工作可继续。审查结果、实现结果、最终验收与提交/发布授权各自独立。

长期任务保留足以恢复的原有修改、当前产物、失败和未完成事项。是否需要工作树由隔离需求和环境决定；既有隔离工作区不重复创建，不凭目录名认定所有权。分支收尾沿用已有 Git 授权和 [收尾规则](../../dw-wrapup/SKILL.md)，不自动提交、推送或删除临时目录。

## 技能验证与自动化边界

确定性检查用于可明确编码的约束，例如 frontmatter、链接、注册入口、文件清单、状态转换和已声明预算。需要判断用户意图、因果、方案价值或语言质量的部分，采用可解释的人工审查；需要模型行为证据时，先限定场景、输入、模型/宿主、次数、预算、停止与资源清理条件，再在有效授权内执行。

按实际缺陷选择场景：正向示例检验产物形状，反例检验适用条件，压力场景检验时间或沉没成本下是否仍遵守边界。比较有指引与无指引时保持其他条件可比，记录失败与方差；未运行就保持未运行。关键词命中需读上下文，排除引用、示例和模板复述，不能作为语义正确性的唯一依据。

结构校验通过只支持结构结论；局部库测试不证明真实入口调用，替身测试不证明宿主副作用，有限场景遵循不证明所有模型始终遵循。实际 DW 入口、库、平台与测试覆盖由 [自动化覆盖清单](../../dw-tooling/references/automation-coverage.md) 说明。本文不提供执行层保证。

## 逐源映射

“沿用”表示 DW 已有规则承接该方法，不再次复制正文；“补充”表示在既有职责中增加上述缺口。全部 15 个 Superpowers Skill 均在下表列出。

| Superpowers `brainstorming` | 规划：理解用途、约束、成功标准，真实方案比较，按复杂度调整深度 | 沿用并补充反例；不移植每阶段审批、只增不减的流程等级、固定文件位置或默认提交；视觉方案复用可用能力 |
| `diagnosing-superpowers` | 诊断/交接：确认会话、事件来源、计划偏离、重复动作、时间成本与证据范围 | 补充会话诊断要点；不移植固定七名分析者、每句路径格式、专属报告目录或禁止按已授权任务修复 |
| `dispatching-parallel-agents` | 协作：按独立问题分解、限定输入和写域、回传后集成检查 | 沿用普通协作；相关失败先查共享原因，不固定按失败数量启动成员 |
| `executing-plans` | 实现/交接：按包连续执行、记录偏离、从真实完成状态恢复 | 补充增量工作包；不移植每步提交、专用 shell 账本、固定审查角色或完成后删除工作目录 |
| `finishing-a-development-branch` | 收尾：核对基线与分支、验证集成结果、保护独有产物 | 沿用收尾/交接；不移植固定选择菜单、重复索取已有授权或从路径名称推断清理所有权 |
| `receiving-code-review` | 验证：先理解、核对技术事实，再逐项处置与检验 | 补充技术核验；不移植任一意见不清便暂停所有工作，或社交措辞禁令 |
| `requesting-code-review` | 验证/协作：明确受审范围、需求、版本和可定位影响 | 沿用并补充修复复核范围；不移植每包强制独立成员与固定轮数 |
| `subagent-driven-development` | 协作/规划：精确工作包、接口衔接、完整回传、避免重复派单 | 补充增量与恢复；不移植固定团队、五轮后停放真实缺陷、自动模型升级或最强模型必审 |
| `systematic-debugging` | 诊断/调试：复现、正常路径对照、反向追踪、单变量因果检验 | 补充因果链与条件等待；不移植第三次失败必然为架构错误、每层全量打印或“错误不可能”断言 |
| `test-driven-development` | 实现：预期原因失败、最小实现、真实行为断言和独立期望 | 沿用 TDD 并补充反例；不移植删除已有实现重做、所有文档必须 TDD 或每次编辑全量测试 |
| `using-git-worktrees` | 规划/收尾：识别既有隔离、保护原工作区、保留基线失败 | 沿用恢复要求；不移植默认安装依赖、默认创建工作树或权限失败后擅改工作位置 |
| `using-superpowers` | 工具：按任务选择已发现能力，适配当前宿主 | 沿用发现流程；不移植 1% 即强制调用、任何响应前必调用或静态平台工具表的执行权威 |
| `verification-before-completion` | 验证：明确要证明的声明，读取实际结果，区分部分证据 | 沿用三 C；不移植每条消息重跑同一检查，仍适用证据可以复用 |
| `writing-plans` | 规划：可独立验收的包、精确接口、全局约束、预期结果和反例 | 补充接口一致性检查；不移植固定两至五分钟、五类风险、完整代码模板或强制新审批 |
| `writing-skills` | 工具/验证：按错误类型写指引，正反场景与对照，排除模板误命中 | 补充验证方式；不移植每次文字编辑必开模型实验、固定样本数、操纵性压力措辞、强制提交发布或有限样本保证遵循 |

其余 DW 职责保持原入口：[优化](../../dw-optimization/SKILL.md) 继续负责代表性基准与等价性，[表述](../../dw-writing/SKILL.md) 继续负责证据强度和清楚表达，[更新](../../check-updates/SKILL.md) 继续负责工具版本与配置检查。本页不改变它们的边界，也不把版本检查解释为真实安装或运行验收。
