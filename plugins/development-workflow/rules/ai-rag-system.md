# RAG 系统设计

## 核心原则
- 文档分块策略: 按语义边界（段落/章节），非固定字符数
- 向量数据库选型: 根据语料规模、过滤/更新模式、延迟目标、运维能力和成本，用代表性数据基准后选择
- 检索+重排序: 仅在离线评估证明收益时组合粗召回与精排；候选数由召回率、延迟和成本共同校准
- 引用溯源: 每个生成结果标注来源文档+位置

## 分块策略
| 文档类型 | 块大小 | 重叠 |
|---------|--------|------|
| 代码 | 函数/类级别 | 导入+签名 |
| 文档 | 语义完整的段落/章节 | 保留解决跨边界指代所需的上下文 |
| 对话 | 完整轮次 | 上一轮 |

## 检索增强
- Hybrid search: 向量 + BM25 关键词
- Reranker: cross-encoder 精排
- 查询重写: 用户问题 → 多角度检索查询

## 工具选择
- 先发现当前环境可用的检索、嵌入、重排和评估能力，不固定依赖某个 MCP 或供应商
- 优先复用仓库已有索引与评估集；新增外部服务前确认数据授权、隐私、成本和回退方案
- 用带相关性标注的代表性查询评估召回、答案正确性、引用准确性、延迟和成本，再决定组件与参数
